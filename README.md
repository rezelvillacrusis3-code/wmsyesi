# YESI Google Sheets Fulfillment WMS

Source package for a Netlify-hosted warehouse application with Google Sheets records, private Google Drive documents and Google staff sign-in. This is a new project, separate from the earlier recovered web and desktop apps.

**Nothing has been installed, deployed or connected to a real Google account.** The package has no seeded clients, inventory, orders, demo staff or authentication bypass. IT must configure Google and Netlify before live access works.

## Implemented workflow

1. Admin enables staff Google accounts and roles.
2. Admin or Manager creates clients, products, locations and approved assembly components.
3. Receiving staff records inspections and posts CSV inbound rows. Posting creates inventory movements and a receipt record.
4. Managers import orders or assemblies and allocate FEFO stock. Allocation reserves units without deducting on-hand quantities.
5. Pickers confirm the stock-position code and quantity. Packers independently scan the picked items.
6. Dispatch staff creates shipment manifests from packed order lines. Dispatch records outbound movements only after every allocated unit is packed.
7. Receiving staff records returns against shipped tasks, with damaged returns quarantined.
8. Finance creates client receivable or supplier payable invoices, records payments and reviews unpaid balances by currency.
9. Authorized staff uploads client documents, including invoice PDFs and delivery documents, to private Google Drive storage.

Current Stock is calculated from the movement ledger. Every write is authorized by role and journaled with a request ID. Interrupted prepared transactions are replayed by record ID before another request is served.

## Contents

- `web/`: HTML, CSS and browser JavaScript. All displayed warehouse figures come from the connected records.
- `core/engine.mjs`: shared validation and fulfillment business logic.
- `google-apps-script/Code.gs`: Google Sheets persistence, signed gateway, file storage and setup.
- `google-apps-script/Engine.gs`: generated business engine; generated by `npm run build`.
- `google-apps-script/appsscript.json`: V8 runtime and required Google scopes.
- `netlify/functions/wms.mjs`: server-side Google token verification and signed Apps Script proxy.
- `templates/`: empty CSV headers for inbound, orders and invoice lines.
- `docs/`: setup, operating instructions, schema, permissions and acceptance tests.
- `tests/`: automated business, authentication, browser rendering logic and transaction recovery tests. Test fixtures are not loaded into the application.
- `dist/`: built frontend. No Google sign-in client is baked into this review build.

## Build and review

Node.js 22 or later is required for build and tests. No npm dependencies need installation for these commands.

```powershell
npm.cmd run verify
```

Google Identity Services is loaded from Google's official browser library after configuration. Netlify provides the server runtime. The Google account and deployment setup are described in `docs/IT_SETUP.md`.

## Verification status and operating limits

Automated tests cover the receive-to-dispatch flow, returns, serials, FEFO, reservations, roles, client isolation, invoice arithmetic, overpayments, duplicate imports, Google token validation, and replay of an interrupted Sheets write. Syntax/build checks cover the frontend, Apps Script and Netlify function.

No live Google Sheets, Drive or Netlify integration has been tested. IT must complete `docs/ACCEPTANCE_TESTS.md` against a new test environment before production use. This source package is not a claim of a live, commissioned installation.

Google Sheets and Apps Script have execution, response and daily quotas. The app sends up to 200 rows per import/allocation transaction and splits large selections into shipment manifest parts of up to 200 order lines. Shipment parts are dispatched separately. Document uploads/downloads are capped at 4 MB per file. This edition is appropriate for a measured departmental workload; it is not a high-throughput SQL warehouse engine. Live load tests are required for your shipment sizes. See `docs/LIMITS.md`.

Billing covers invoices and payment balances. It does not implement a complete general ledger, bank reconciliation, payroll or tax filing. IT and Finance should confirm invoice fields and retention requirements before issuing official invoices.

## Languages

JavaScript for browser, business engine, Node/Netlify functions and Google Apps Script; HTML/CSS for the interface; JSON/TOML for configuration. It does not depend on the unrecoverable scripts from the damaged laptop.
